# 抖音聊天导出助手 / Douyin Chat Exporter

一个计划中的开源 Chrome / Edge 扩展：由用户在抖音网页版自行登录，选择**一个会话**，将其**完整历史消息**导出到自己的电脑。

> **项目状态：M1.2 原始内容试采集（0.1.7，尚非完整备份工具）。** 可在滚动时采集网页实际显示的文字到本机 JSON/TXT；不验证消息 ID、发送者、时间、最旧边界及语音转写。原 M0 不读取聊天正文的诊断功能依旧保留。

## 第一版目标

- 一次处理一个由用户主动选择的会话。
- 自动上翻并逐批保存历史（用户已确认网页版可以翻到最早消息），而不只读取屏幕当前显示的消息；如遇网页虚拟列表/遗漏，再评估当前登录态的分页接口。
- 保留时间、发送者、消息类型、消息 ID、文本、附件元数据和原始平台顺序。
- 语音调用抖音网页内建的右键「转成文字」，将识别结果作为文本写入导出文件；不接第三方语音识别服务。
- 导出 JSON（主格式）以及便于阅读的 TXT。HTML 可在消息一致性验证后加入。
- 未拿到完整历史边界、出现漏抓或语音转写未完成时，**不能报告“全部完成”**；独立呈现历史采集和语音转写两种状态。
- 无云端中转；无需额外账号；无自动发送、自动回复及联系人采集。

详见 [实施计划](docs/IMPLEMENTATION.md)、[验收标准](docs/ACCEPTANCE.md)、[安全规范](docs/SECURITY.md)。

## 本地安装与验证

1. 在 GitHub Actions 的 `CI` 工作流中下载 `douyin-chat-exporter-extension`，或在源码目录执行 `npm run build`。
2. 在 Edge 打开 `edge://extensions`，或在 Chrome 打开 `chrome://extensions`。
3. 开启「开发人员模式」→「加载解压缩的扩展程序」→ 选择 `dist/extension` 文件夹。
4. 在浏览器中自行登录 `https://www.douyin.com/`，打开一位联系人的私信窗口。
5. 点击扩展图标 →「检测当前页面」。只显示统计摘要，不采集对话正文。记下 `scrollableRegions` 中的 `scrollTop`。
6. 在聊天历史区域向上滚动几屏，再次检测；两个结果中 `scrollTop` 发生变化的候选区域通常就是聊天滚动容器。

**连续索引测试（M0.4）：** 打开聊天后点击「开始连续索引测试」，网页右上角会出现临时面板。用户自己缓慢向上滚动几屏，再按面板中的「停止并生成报告」。报告只含 `data-index` 数字和未观察索引统计，不含聊天正文。它用于验证虚拟列表监听效果，**不是聊天记录备份**。

**本地文字试采集（M1.2 / 0.1.7）：** 打开一个私信会话，从较新聊天位置点击「开始本地聊天文字采集（实验）」。回到网页，在**同一个会话**中手动向上缓慢滚动到希望读取的历史范围；右上角面板显示已缓存的列表项数。点击「停止并准备下载」，自行下载 JSON 与 TXT。无需安装 Node.js，也不需要调用第三方服务。

- JSON 的 `entries[]` 是**网页虚拟列表的原始条目**，不是已解析的可靠平台消息：`dataIndex` 不是永久消息 ID；`visibleText` 可能含日期标签、语音下方的转写文字或其他 UI 文本；`mediaMarkers` 只计数网页媒体元素，并不下载媒体。
- 采集进行时数据暂存在网页内存：刷新网页、关闭标签页、误关闭面板会丢失尚未下载的数据；这一步还**没有自动滚动、断点续传、自动右键语音转写、会话绑定或最早边界判定**。
- 导出固定标记 `capture.status: partial`、`voiceTranscription.status: not-verified`。索引没有缺口也不能改成“完整”。
- **保护隐私：** 导出文件包含真实私聊正文，不要贴到 GitHub Issue、PR、公开聊天或发给开发者。若需反馈，只告诉我们**采集条目数、索引范围、未观察索引数、无文字数、是否混入其他内容**，不要复制 `entries[]`。
- **0.1.6 采集准确性修正：** 只处理实时列表的直接子项，不再读取已经移除的节点或内部的 `data-index`；同一段文字在至少 180ms 内保持一致才归为 `captureConfidence: stable`。统计将“瞬时文本变化”、“稳定后的真正冲突”、“尚未稳定的变化”和“暂存但未稳定条目”分开。即使显示为稳定，也不意味着平台消息 ID/时间已验证。
- **0.1.7 阅读顺序：** 用户确认 0.1.6 不再出现串位或重复，但原导出顺序是较新在上、较旧在下。新版本对 JSON `entries[]` 和 TXT 采用 `dataIndex` 降序，按**较早在上、较近在下**排列。只调整本地导出顺序，不影响滚动采集、索引缺口统计或完整性标记。

Windows 上的 `npm run build` 需要 Node.js 22+；如没有 Node.js，可以直接将 `extension/` 作为解压缩扩展加载。

## 开发与发布

- `main`：经过人工验收的稳定代码。
- `feature/*`：各开发任务分支，经过 Pull Request 审核再合并。
- CI：语法/静态约束检查、单元测试、构建扩展包并上传 Actions artifact。
- 正式版本：完成真实账号验收后手工打 `vX.Y.Z` 标签；不自动向商店发布。

```bash
npm test
npm run build
```

## 参考项目

- [TeamBreakerr/douyin-chat-export](https://github.com/TeamBreakerr/douyin-chat-export)：已有独立服务形式的历史消息采集和媒体处理实现，可研究其公开技术方案。
- [Chrome `scripting` API](https://developer.chrome.com/docs/extensions/reference/api/scripting)

本仓库目前没有复制参考项目代码。后续若使用第三方代码，应先确认许可证、标注出处并遵守义务。

## 提醒

本工具只处理用户本人已获授权访问的聊天。抖音网页与消息接口可能变更；历史消息是否仍保留、是否可读取，要以实际服务端分页返回为准。
