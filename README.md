# 抖音聊天导出助手 / Douyin Chat Exporter

一个计划中的开源 Chrome / Edge 扩展：由用户在抖音网页版自行登录，选择**一个会话**，将其**完整历史消息**导出到自己的电脑。

> **项目状态：v0.4.2，修正真实消息时间并增加一键自动滚动。** v0.4.0 已收到用户真实 Edge 环境的积极反馈，但 v0.4.1 把 IM 消息排序字段误作 Unix 时间导致日期错误。v0.4.2 根据消息 ID 解析真实发送秒数，独立复用旧版已经验证的滚动机制帮助长会话触发历史加载；原生 API 分页与语音转写逻辑保持不变。没有 `debugger` 强权限。

## 第一版目标

- 一次处理一个由用户主动选择的会话。
- 优先使用抖音当前登录态的 IM 分页接口获取历史（不依赖页面滚动），旧版 DOM 方式备用。
- 保留时间、发送者、消息类型、消息 ID、文本、附件元数据和原始平台顺序。
- 语音通过抖音网页自身的原生识别接口批量转写；不接第三方语音识别服务，也不模拟鼠标右键。
- 导出完整 JSON、便于阅读的 TXT 与无需联网的 HTML 聊天气泡阅读版。
- 未拿到完整历史边界、出现漏抓或语音转写未完成时，**不能报告“全部完成”**；独立呈现历史采集和语音转写两种状态。
- 无云端中转；无需额外账号；无自动发送、自动回复及联系人采集。

详见 [实施计划](docs/IMPLEMENTATION.md)、[验收标准](docs/ACCEPTANCE.md)、[安全规范](docs/SECURITY.md)。

## 安装与运行 v0.4.2

1. 从最新 GitHub Actions `CI` 下载唯一安装包 **`douyin-chat-exporter-extension`**，解压至包含 `manifest.json` 的文件夹（如里面还有一个 ZIP，请再次解压）。也可执行 `npm run build` 生成 `dist/extension`。
2. 在 Edge 打开 `edge://extensions`，或在 Chrome 打开 `chrome://extensions`。
3. 开启「开发人员模式」→「加载解压缩的扩展程序」→ 选择解压文件夹。旧版用户先下载需要的文件，再替换旧扩展或卸载后安装新版，不要同时运行多套插件。
4. 在浏览器中自行登录 `https://www.douyin.com/`，打开一位联系人的私信窗口。
5. 点击「**启动 v0.4.2 API 导出**」。若面板尚未捕获会话标识，点击新增的「**自动滚动到最早消息**」，待停止后再开始导出；滚动阶段不读取消息正文。必要时仍可手工切换其他聊天再切回。这个预备滚动只是触发抖音自己加载历史，**不是**最终的历史完整性证明。
6. 填写本地会话标签，按「开始 API 历史导出」。**开始后不要切换会话**。程序逐页读取服务端消息，依平台排序字段（`created_at_us`）保持原顺序，并尝试批量原生语音转写。
7. 你可以在半程停止下载部分结果，也可以暂停、继续，或在再次捕获同一会话 ID 后恢复 API 断点。优先检查 TXT/HTML；JSON 有单独的采集与语音状态报告。
8. 若 API 无法运行，点击插件中的「**旧版网页滚动导出（已验证正文）**」，仍可使用此前验证通过的正文采集能力。

**v0.4.2 时间修正：** v0.4.1 把 Protobuf 字段 `created_at_us` 当成 Unix 微秒时间戳，实际上它是单调排序键。真正的 Unix 秒时间戳来自 `server_id` 的高 32 位。新版本据此生成 JSON `createdAt`，TXT 按北京时间（UTC+8）分日期且每条文字/成功语音显示 `HH:mm`，HTML 在气泡下方显示分钟。旧版缺失真实时间的 DOM 记录直接省略。排序仍保持原字段，防止 1–12 秒内的服务端顺序与显示秒数差异影响聊天顺序。

**兼容旧断点：** v0.4.0/v0.4.1 本地 API 断点仍可恢复；生成导出档案时会用稳定 `platformMessageId` 修正旧时间。**已经下载的旧 JSON 文件不会被自动篡改**，如需无须重抓地修正既有文件，可另行加入纯本地 JSON 重新渲染入口。

**技术与限制：** 此 API 是从网页行为观察到的非公开接口，可能因抖音改版、登录态或跨域策略失效。单聊的 `short_id` 未必出现在页面 store；当前方案需要观察抖音网页自己发起的请求。绝不清理你的 SDK 缓存、提取登录 Cookie、绕过安全验证或把部分历史冒充完整结果。详见 [v0.4.2 技术说明](docs/RELEASE_0.4.2.md)。

## 旧版网页滚动导出（作为回退保留）

**重要限制：** 当前 Douyin 页面有 `data-index` 虚拟列表，但该值不是经平台确认的永久消息 ID。`v0.2.0` 有自动滚动、稳定文字快照和覆盖率校验，但仍无法从已掌握的网页结构验证每条消息的永久 ID/真实发送时间及服务端完整边界。发送者根据布局推测，类型和语音位置也采用保守启发式规则；不确定时标记 `unknown`。因此报告可能保持 `partial`，不应伪装成全量备份。

**语音转写：** 只尝试打开网页自己的右键「转成文字」菜单。若页面拒绝程序合成的右键事件，标记 `manual_required`，允许你在原网页手工转换再「重扫当前屏幕」。转写无文字或超时会保留 `pending/failed`。没有接入第三方语音识别服务，抖音原生功能自身可能通过其服务器处理语音。

**真实语音样本修正：** 用户提供的 854 条原始列表项中，至少 27 个是类似 `28"`、`6"`、`1"` 的语音秒数标记，之前错误识别为 text。v0.3 需同时看到独立秒数标记和消息内部的 canvas 才推断为 voice（canvas 在普通文字消息中也很常见，不能单独当作语音）。

**历史增强版说明：** v0.3.1 的增强鼠标右键方案在 Git 历史中保留，但 v0.4 发布包不再附带 debugger 调试后台，也不需要该强权限。

**简洁阅读版：** TXT 与 HTML 只突出普通文字和已转写语音；日期分隔保留为小标题，其他媒体合并为「其他消息」，未转写语音只在结尾统计。没有索引、时间未知、JSON 媒体计数等内部字段。技术明细 TXT / JSON 保留未完成状态及所有原始条目，避免静默丢失。

**断点与存储：** 新版本增加 `storage` 权限，用于将当前会话的正文和位置保存到浏览器扩展本地 `chrome.storage.local`，不上传。Chrome 默认配额约 10 MB；超过配额会停止/暂停并提示本地下载，不能保证继续断点续采。卸载扩展或手动删除断点会删除缓存，已下载文件不受影响。

**禁止提交私聊数据：** JSON/TXT 和断点都可能包含真实私人消息。向开发者反馈时只发送数量、失败状态、脱敏 DOM 结构，不要上传正文、截图中可识别信息、URL Token 或 Cookie。

## 保留的 M0/M1 诊断工具

**连续索引测试（M0.4）：** 打开聊天后点击「开始连续索引测试」，网页右上角会出现临时面板。用户自己缓慢向上滚动几屏，再按面板中的「停止并生成报告」。报告只含 `data-index` 数字和未观察索引统计，不含聊天正文。它用于验证虚拟列表监听效果，**不是聊天记录备份**。

**本地文字试采集（M1.2 / 0.1.7）：** 打开一个私信会话，从较新聊天位置点击「开始本地聊天文字采集（实验）」。回到网页，在**同一个会话**中手动向上缓慢滚动到希望读取的历史范围；右上角面板显示已缓存的列表项数。点击「停止并准备下载」，自行下载 JSON 与 TXT。无需安装 Node.js，也不需要调用第三方服务。

- JSON 的 `entries[]` 是**网页虚拟列表的原始条目**，不是已解析的可靠平台消息：`dataIndex` 不是永久消息 ID；`visibleText` 可能含日期标签、语音下方的转写文字或其他 UI 文本；`mediaMarkers` 只计数网页媒体元素，并不下载媒体。
- 采集进行时数据暂存在网页内存：刷新网页、关闭标签页、误关闭面板会丢失尚未下载的数据；这一步还**没有自动滚动、断点续传、自动右键语音转写、会话绑定或最早边界判定**。
- 导出固定标记 `capture.status: partial`、`voiceTranscription.status: not-verified`。索引没有缺口也不能改成“完整”。
- **保护隐私：** 导出文件包含真实私聊正文，不要贴到 GitHub Issue、PR、公开聊天或发给开发者。若需反馈，只告诉我们**采集条目数、索引范围、未观察索引数、无文字数、是否混入其他内容**，不要复制 `entries[]`。
- **0.1.6 采集准确性修正：** 只处理实时列表的直接子项，不再读取已经移除的节点或内部的 `data-index`；同一段文字在至少 180ms 内保持一致才归为 `captureConfidence: stable`。统计将“瞬时文本变化”、“稳定后的真正冲突”、“尚未稳定的变化”和“暂存但未稳定条目”分开。即使显示为稳定，也不意味着平台消息 ID/时间已验证。
- **0.1.7 阅读顺序：** 用户确认 0.1.6 不再出现串位或重复，但原导出顺序是较新在上、较旧在下。新版本对 JSON `entries[]` 和 TXT 采用 `dataIndex` 降序，按**较早在上、较近在下**排列。只调整本地导出顺序，不影响滚动采集、索引缺口统计或完整性标记。

Windows 上的 `npm run build` 需要 Node.js 22+；如没有 Node.js，可以直接将 `extension/` 作为解压缩扩展加载。

## 开发与发布

- `main`：经过人工验收的稳定代码。
- `feature/*`：各开发任务分支，经过 Pull Request 审核再合并。
- CI：语法/静态约束检查、单元测试、构建扩展包并上传 Actions artifact。
- 正式版本：完成真实账号验收后手工打 `vX.Y.Z` 标签；不自动向商店发布。

```bash
npm test
npm run build
```

## 提醒

本工具只处理用户本人已获授权访问的聊天。抖音网页与消息接口可能变更；历史消息是否仍保留、是否可读取，要以实际服务端分页返回为准。
