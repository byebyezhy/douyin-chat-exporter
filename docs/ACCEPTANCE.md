## 定义

- `complete`（消息采集）：网页的历史终止边界/平台“没有更多”已经明确确认；没有失败批次、遗漏或已知缺口。这表示**可访问历史已遍历**，不意味着平台永久保存了所有曾发送消息。
- `partial`：尚未读到服务端的最旧边界，包含用户暂停/取消或仍在采集中。
- `incomplete`：某一页失败无法恢复、游标循环、数据校验失败或存在已知缺口。
- 语音转写另有 `pending / success / failed / unavailable`；只有所有可转写语音均已完成时，才报告语音转写全部完成，失败条目可重试。
- 其他媒体另有 `downloaded / metadata_only / unavailable / unsupported` 状态；不与消息完整性混为一谈。

## 必须通过的情景

| 编号 | 情景 | 预期 |
| --- | --- | --- |
| A01 | 当前会话只有屏幕上 50 条，实际有多批历史 | 自动上翻且**边加载边保存**，直到验证最早边界，不以 50 条结束 |
| A02 | 网络中断，第 4 批失败 | 导出报告为 incomplete，不显示完整成功 |
| A03 | 同一批重复返回 / 消息重复 | 不产生重复 ID，记录异常并必要时终止 |
| A04 | 相同时间戳多条消息 | 按序列号或稳定后备键排序，顺序可重复得到一致结果 |
| A05 | 表情、语音、分享等不能解码 | 保留占位、类型、消息 ID、时间及错误原因，不丢消息 |
| A06 | 用户选择聊天 A 后意外切换到 B | 停止或绑定 A，不混入 B 的消息 |
| A07 | 用户取消后重新开始 | 不将上次 partial 文件误标 complete，重复消息可去重 |
| A08 | 页面要求重新登录 / 验证码 | 提示用户处理，不能绕过或自动提交凭据 |
| A09 | 拿到 JSON 后重新解析 | 消息总数、唯一 ID、会话 ID、完成状态保持一致 |
| A10 | 检查发布包 | 没有抓包、Cookie、Token、私聊样本，权限符合最小化原则 |
| A11 | 页面存在三条语音，右键可「转成文字」 | 逐条触发平台原生转写，文本归到正确消息 ID，无第三方 ASR 请求 |
| A12 | 一条语音转写超时或没有选项 | 状态为 failed/unavailable，文件保留语音占位，不谎称语音已全部转写 |
| A13 | 虚拟列表滚动时回收旧消息节点 | 由于每批都已保存，最终导出仍含此前读取的消息 |
