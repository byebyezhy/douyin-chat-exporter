# v0.3.0：原生语音增强与简洁阅读版

## 经用户确认的真实问题（不含私聊正文）

- v0.2 自动历史滚动正常、时间方向正确、导出普通文字内容准确。
- 用户上传的 TXT 中共有 854 个列表项；从无关私人内容中仅提取结构特征：`type=text` 796，`unknown_media` 45，`image` 13。
- `canvas` 出现在 482 个条目中，不能据此断言是语音；另有至少 **27 个**独立文本形式的 `28"`、`6"`、`1"` 等秒数项，全部被 v0.2 当作普通 text，因而未进入转写流程。
- 多数条目的 img/canvas 标记来自网页组件而非实际附件，技术明细不适合人类阅读。

## 本次实现

1. 语音候选规则同时要求秒数形式和 canvas（或者明确的语音辅助属性），并在当前列表项定位右键目标。
2. 先尝试普通网页右键；可选增强模式使用**用户主动授权**的 Chrome debugger 输入事件模拟可信左右键，仅限当前抖音标签。失败标记 `manual_required`；不调用第三方 ASR。
3. 使用网页本身生成、显示在语音下面的转写文字；保存来源、状态和置信度，允许手工转换后重扫。
4. 简洁 TXT 和离线 HTML 阅读版，隐藏技术索引、未知时间、媒体计数；可读内容只突出普通文字与已转写语音，其他媒体合并为简洁占位。
5. JSON 和技术 TXT 仍保留完整技术诊断及失败细节，不将未知媒体当作文字，也不伪造成功。

## 权限与隐私

- 必需：`activeTab`, `scripting`, `storage`。
- 可选：`debugger`，只通过用户点击浏览器弹窗申请；用户可随时撤销，不会安装即授权。
- 增强后台只发送受限的 DevTools `Input.dispatchMouseEvent`，每次动作后 detach；无网络数据访问、凭据获取或外部服务器。
- 所有归档内容仍只存在用户本地，阅读 HTML 有 HTML 转义与禁用外部脚本的 CSP。

## 待真实环境验证

抖音是否接受通过 Chrome 调试器发出的右键、菜单能否自动定位和点击、转写文本是否及时显示，仍须用户在 Edge 内最终验证。若权限未授权或页面拒绝，则保留人工辅助，不报告全部成功。
