# 第一版实施计划（单会话 / 完整历史）

## 2026-10-24 最新进展：v0.2.0 完整功能候选版

在用户确认 v0.1.6 的文字不再串位、v0.1.7 的顺序正确后，按要求将后续工作合并为一次开发版本：

- 主界面一次启动自动滚动，监控实时虚拟列表，并按列表索引进行重叠采集/保守去重。
- 通过本地标签、当前网址、列表 DOM 是否重建与索引重置检测降低会话串位风险。**由于尚无平台稳定会话 ID，不能声称绑定已完整验证。**
- 暂停、继续、停止、下载以及 `chrome.storage.local` 断点；保存数据仍在本机，超过配额将提示失败并允许下载内存数据。
- 时间仅解析明确带时区或 10/13 位 Unix 时间戳；发送者采用布局启发式，保留置信度；未知类型保留。
- 语音在识别到足够强的 UI 信号时尝试触发抖音原生右键菜单，并读取后续追加文字。拒绝合成事件时进入 `manual_required`，不调用第三方 ASR。
- 完整性与语音转写结果分开报告；未验证永久消息 ID、历史终止边界或会话绑定时保持 `partial`，不会把列表停止滚动当成服务端完整。
- 新增合成 DOM 自动滚动/原生右键转写模拟测试、导出排序测试、异常与覆盖率单测；真实 Edge/Douyin 集成测试仍需用户进行一次最终验收。

本版本是**功能候选**，不是已经获真实平台验证的完整消息备份软件。仅在事实证据支持的地方声明完成。

**交付定义：** 用户在 Edge/Chrome 自行登录抖音网页版，选择单个会话，明确触发导出；只用可合法访问的登录会话读取消息；保存结构化 JSON 到本机。第一版优先保证“不会悄悄遗漏消息”，其次才是体验和媒体展示。

## 方案与决策

- 产品形态：Manifest V3 浏览器扩展，默认不依赖服务器。
- 数据入口：**优先网页自动上翻 + 每批采集 + 持久化去重**。用户已确认网页版能够一直翻到最早聊天。若有虚拟列表回收元素，应在每次滚动前后采集，避免只读取最终 DOM；如发现漏抓或无法判断边界，再评估当前登录会话的消息分页接口。
- 用户态：使用浏览器内现有抖音登录会话。插件不得索要账号密码或导出凭据。
- 范围：用户主动打开的**一个**聊天对象，不批量遍历通讯录，不发送消息。
- 输出：结构化 JSON 为完整归档的权威格式；TXT 为从同一消息集合派生的阅读格式。HTML 后置。
- 语音：使用抖音网页版自带的右键「转成文字」功能，读取界面生成的文本并附到对应语音消息；**不集成第三方语音识别 API**。保留 `pending/success/failed/unavailable` 状态，失败可单独重试。
- 媒体：每种消息必须保留类型、可用文本、引用/元数据和获取状态；二进制媒体本地化放在后续独立里程碑，不能把“链接未下载”描述为“媒体已备份”。
- 非目标：自动登录、服务端托管、多账号、爬取非本人可见聊天、绕过风控验证码、在线 AI 上传。

## M0：登录态与接口可行性确认（当前）

1. 安装诊断扩展（仅用户点击后启动）；检查能否访问 `www.douyin.com` 页面结构。
2. 用户手动打开某个私信窗口：已确认能够一直上翻到最早消息。下一步确认消息容器、滚动区域、虚拟列表行为和终止提示，设计逐批采集以避免 DOM 回收导致遗漏。
3. 在一条真实语音上验证右键菜单里的「转成文字」以及转写完成后文字所在 DOM；检查扩展能否可靠触发此网页操作（普通合成右键事件有可能不被接受）。
4. 如 DOM 采集无法自证完整，再在用户**本地**开发者工具观察消息分页：确定数据格式、消息 ID、时间单位、会话 ID、分页游标与边界标记。禁止将原始 HAR/Cookie/请求头提交到公开仓库。
5. 使用**合成测试数据**固化采集器/消息类型模型；任何私有抓包仅停留在本机。
6. 产出结论：可识别最早可得的边界、逐批采集不会漏消息、原生转写是否可自动完成。

**M0 验收：** 能识别消息列表和明确的历史终止边界，采集两个以上滚动批次，并确定原生语音转写的触发/读取方式。若无法确认最早边界或自动右键失败，应明确报告限制，不声称全部完成。

## M1：单会话全量消息采集

1. 识别并绑定用户明确选择的当前会话 ID，显示对方昵称供人工确认。
2. 从最新消息向上自动滚动，**每次新消息出现立即采集并持久化**，不能在滚到最早后才一次性读取 DOM；用户可暂停、取消、重试。
3. 每批去重、验证格式；检测空白批次、列表回收、异常跳页与已知缺口，遇错误显示“未完成”。必要时采用登录会话接口的历史分页作为补强。
4. 以消息 ID 去重，以平台提供的序列字段或时间戳排序；相同时间戳使用确定性次序。
5. 以明确的顶部边界/服务端无更多标志为终点；仅“连续数次不动”不足以自证最旧边界。到达可验证的历史边界且无已知缺漏，才将**消息采集**标记 `complete`。
6. 对语音消息逐条调用抖音原生「转成文字」，等待文字显示后归属到对应消息 ID；失败、超时、不可操作均记状态，允许单独重试。若浏览器禁止模拟右键事件，评估用户辅助操作，不改走第三方转写。
7. 本机导出 JSON/TXT，包含 `captureStatus` 与 `voiceTranscriptStatus` 两个独立状态；文件名含安全处理后的会话别名、时间和导出状态；不自动上传。

**M1 验收：** 既有近千条消息的测试会话可逐批完整导出；故意注入超时、重复批次、断网都不能报成功；重试无重复消息；文件可重新导入并得到一致记录数。含语音的会话必须能将平台已成功转写的文本关联到正确消息。

## M2：消息类型与附件覆盖

1. 对文字、表情、图片、视频、语音、分享、系统通知、撤回、引用、合并转发建立类型适配。语音转文字已属 M1 必需能力，M2 只扩展二进制附件能力。
2. 对不支持的类型保留消息 ID、时间、发送者、原始类型和 `[unsupported]` 状态，不隐式删除。
3. 可选媒体本地化：在不破坏账号安全和站点规则的前提下保存可获得的附件，记录成功/失败和原始引用信息。
4. 复核完整性：**消息记录覆盖率**与**媒体二进制落地率**分开呈现。

## M3：公开发布质量门槛

- Edge/Chrome 真实账号回归；空会话、短会话、超长会话和断网恢复。
- GitHub Actions 测试、权限审查、打包；版本号、Release Notes、安装说明。
- 隐私政策和第三方代码许可审查；绝不提交私有数据样例。
- Release 人工审批，测试版不自动公开宣称“完整”。

## 核心技术风险

| 风险 | 对策 |
| --- | --- |
| 网页虚拟列表回收旧节点 | 滚动时实时保存每一批，必要时用会话接口核对；绝不将最终 DOM 当成全量 |
| 平台只提供部分云端历史 | 明确展示最早可读时间，不承诺超出平台实际返回的数据 |
| 接口/协议升级 | 分离适配层和通用导出层；合成 fixture 回归测试 |
| 连续滚动但不知道是否到顶 | 判断真正边界提示/分页终止证据，不凭“滚不动”就宣称完整 |
| 原生语音右键无法自动触发 | 检测菜单行为，失败则进入用户辅助转写/待处理队列；不接第三方 ASR |
| 游标循环、限速、断网 | 退避重试和继续位置；不规避验证码或访问限制 |
| 私密聊天泄漏 | 仅本地运行、最小权限、无遥测、公开仓库只用合成数据 |
| 表情/图片/语音过期 | 区分消息完整和媒体本地化；明确报告失败资源 |
